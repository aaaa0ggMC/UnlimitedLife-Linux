# 桌面 Froxel 体积雾：实现与评估

## 方案选择

| 方案 | 优点 | 对本场景的主要限制 | 选择 |
| --- | --- | --- | --- |
| 解析高度雾 | 成本低、均匀介质结果稳定 | 难以表达三维雾团、局部灯和遮挡光束 | 保留推导归档，不再用于合成 |
| 每像素视线步进 | 实现直观，可精确终止于表面 | 分辨率×步数×光源采样开销，重复计算相邻射线 | 不作为当前主路径 |
| Froxel 视锥网格 | 多像素共享密度与光照，可独立调整空间分辨率和历史过滤 | 需要额外体积存储；近处与阴影边缘受离散化影响 | 当前主路径 |
| 光线追踪／路径追踪体积 | 可扩展更复杂的可见性与多次散射 | 硬件要求、采样数和去噪成本高 | 不引入当前桌面示例 |

以上是工程取舍，不是已有同机 benchmark 的结论；不同方案还未在相同硬件上实测对比。

## 帧图与所有权

```text
acquire（等待 frame/image fence）
  → 读取该 image 上一轮 GPU timestamps（无 WAIT）
  → 上传该 image 的 CameraFogUbo
  → GraphicsContext::begin(before_render)
      → 重置该 image 的 timestamp 区间
      → sun + point light cube-only depth render passes
      → injection compute：局部 RGB 散射系数 + A 消光
      → compute write → compute read 屏障
      → temporal compute：历史重投影、拒绝和裁剪
      → compute write → compute read 屏障
      → integration compute：沿深度前向积分
      → compute write → fragment read 屏障
  → 场景与天空：三线性采样积分体积
  → UI → end/submit/present
```

阴影 pass 的外部依赖覆盖 early/late depth write → compute/fragment shader read，结束时自动切换为
`DEPTH_STENCIL_READ_ONLY_OPTIMAL`。主场景无论采用 dynamic rendering 还是 legacy render pass，
阴影阶段都在主渲染作用域之前独立执行。

所有体积与阴影资源按交换链图像独立，避免多帧同时读写同一张阴影或体积。
Inspector 修改共享实例缓冲前显式等待设备空闲；普通全局参数修改不再触发整个实例批上传。

## 光照、消光与阴影

局部介质满足：

```text
sigma_t(p) = weather_density(p) * animation(p)
q(p, v) = sigma_t(p) * albedo * fog_color * incident_lighting(p, v)
T_segment = exp(-sigma_t * ds)
S_next = S + T * q * (1 - T_segment) / sigma_t
T_next = T * T_segment
final = background * T + S
```

积分使用每格常系数的解析解，极小光学深度使用一阶展开避免消减误差。起止距离仍是径向光程；
网格切片本身使用相机空间 Z 的对数分布，边缘射线以实际长度积分。

全局介质默认从相机位置起积分，不带近端空洞。旧的 `fog.start=8` 保留为可选的艺术裁剪距离，
只有勾选「启用全局近端裁剪」才参与视线积分；默认关闭，且不改变光照路径中的世界空间介质密度。
无局部介质时由积分范围裁剪；有局部介质时仅在注入中裁掉全局分量。所有路径共用 helper，
局部 FogVolume 始终保留近场；start 仅是可选全局近端裁剪，不存在 end 积分终点。
这个开关会使旧历史失效，避免切换时保留旧的相机近端空洞。

靠近后蓝色光晕变淡可能有三种不同原因：旧 start 删掉近场散射、真实可见光程缩短，以及亮灯核经显示映射趋白。
这不能仅凭单帧截图归为一种错误。可切换裁剪开关并使用「散射」调试视图区分介质贡献与灯核；
物理模式不保证远近颜色完全相同，只消除人为的 start 距离阈值。

表面采样不再按对数切片比例线性混合累积 S/T，而是由相邻积分边界重建常系数段，
按表面所在的实际径向光程计算部分 Beer–Lambert 积分（只保留可选 start 裁剪）。
XY 仍是双线性近似，因此此重建不等同于每像素重新步进真实场。

HG 使用 `p(mu)=(1-g²)/(4*pi*(1+g²-2*g*mu)^(3/2))`，其球面积分为 1。
旧实现使用单位平均值的 HG，直接乘局部灯强度会额外放大 4π 倍；现已修正。
局部灯表面照明使用 Lambert 的 `albedo/pi`；太阳色沿用原先“漫反射照度除以 pi”的控件尺度，
注入介质前换回照度。这些量仍是相对场景单位，不是经过真实灯具标定的流明。

太阳使用固定岛屿中心 `(0,8,0)` 的正交阴影图，方向变化时重绘；地图位置不跟随相机，避免相机移动导致阴影投影抖动。
覆盖区外按可见处理，**不是无限世界阴影**。点光按位置与范围渲染 6 面立方体阴影（每帧最多 5 盏）。
两种阴影都绘制真实模型及实例几何，不用包围盒代替模型。

局部点光具有有限范围和平滑距离衰减；最近 5 盏按范围生成 cube shadow。水面是独立的半透明批次，不写深度、不进入 shadow pass；水上/水下通过相机高度与水面片元高度逐片元选择顶面或底面，丢弃侧面以避免方块网格叠加。
光源到采样点的介质透过率额外用 0–8 步近似；0 表示关闭，太阳光程为可配置有限长度，
并非无限大气积分。此步骤不是多次散射，也不代替几何阴影。

局部灯附近按体元长度自适应使用四个分层深度样本，平均的是源项和消光系数，
不是取高亮峰值代替整段。点光的体积衰减另用体元横向 footprint 过滤近场，
聚光锥也按角 footprint 与发射体半径取较大者过滤，减轻远距离粗格下的白球和光锥棋盘边缘。
这些是有限体元抗锯齿近似，并非精确的面积灯或能量守恒体积卷积；不能保证所有视距下亮度完全一致。

#### 已删除的陈旧参数

以下字段只写不读或已无对应代码路径，已从 UBO／组件／界面移除：

- `CameraFogUbo::previous_camera_position`：时域重投影只用 view/proj，从未读取。
- `fog_anim_factor(p, with_wave)` 的 `with_wave`：解析天空雾删除后恒为 true。
- 点光只有位置/颜色/强度/范围/半径；不再有聚光灯派生结构。

CPU 侧 `CameraFogUbo` 现为 784 字节，静态断言与一致性检查同步更新。

#### 重复工作削减与编辑器回归

- 每张交换链图像各自缓存两张阴影图；首次使用（含关闭状态）仍清空并转为可采样布局。
  开关、光源投影矩阵、几何版本变化时重绘，成功提交／呈现后才标记有效；失败会使全部缓存失效。
  阴影资源重建会清空缓存。相机移动和雾动画不改变阴影图；检查器修改目前保守地使几何版本失效。
- 局部雾快照变化时增加 revision，各交换链图像在 fence 等待后按需上传；重建的缓冲强制首次上传。
  ECS 快照比较仍每帧执行，未做依赖隐式 dirty 标记的激进缓存。
- 注入阶段零散射系数跳过光照计算，保留消光项；不使用阈值丢弃微弱散射。
- 相同 yaw/pitch 不再使相机变换失效；检查器关闭时不登记实体字段。
  修复了折叠组件只隐藏首个字段，以及多个点光重名控件 ID 冲突。
- `editor-check` 子命令实际调用编辑、保存／载入及缓存条件，并创建无后端 ImGui 帧检查字段行为。
  存档写出固定精度小数以绕过当前 alib6 JSON 写出整数形式浮点值后无法通过自身严格类型校验的问题。
  所有载入参数、数量及外部 RAW 纹理尺寸先校验；错误文档不会替换当前布局。

这些检查不含完整场景的阴影缓存同步、按钮点击和性能测量；未声称实际 FPS 或 GPU ms 已改善。

#### 有限发射体与能量约定

旧的灯块 emission=3 会在 LDR 截白，后改为 emission=1 又使无雾灯体偏暗，仍与实际照明光强不一致。
本轮不再使用这个独立预览常数：两盏灯采用球形发射体，默认半径 R=0.11，光强 I 对应表面辐射亮度
`L=I/(pi*R²)`。可见球体、表面照明和雾散射使用同一组 I/R；球体内不注入雾。
它们使用 `SurfaceMaterial.voxel=-1` 的自发光分支，不接受自身点灯／太阳的表面照明。
灯核本身是均匀自发光，**不乘聚光锥衰减**：锥描述的是射出的光束，不是可见灯泡的亮度，
因此从锥外（相机常见位置）看灯仍是亮的，不会出现黑球。
旧实现把 `end` 当作所有表面的积分终点，超过后透过率保持常数；上一轮只给灯核加远端修正，
仍没有解决普通表面拉远后不继续淡化的问题。现已撤掉灯核特例，所有表面统一采样覆盖相机视锥的 Froxel。
网格深度终点取相机 far，不再限制径向光程（斜射线可以比 far 更长）；普通表面和灯核都积分到自身位置。
运行期组件与界面、天气、快捷键已移除 end；旧 AppConfig.fog.end 仅 optional 兼容读取。
这不是对灯核辐射亮度再乘一次 `1/d²`，无介质时保持原亮度。
同时修正精积分无局部雾时未实际屏蔽全局 `start` 以前介质的问题；局部雾不受该全局裁剪影响。
聚光发射体的锥边缘半影取 `max(froxel footprint, R)/距离`，表面与体积两条路径一致；
体元小于发射体视角时不会被单次采样切成硬边，但仍是有限锥近似，不是精确的面积光软阴影。
这些量是相对场景辐射单位，不是经真实灯具标定的流明或瓦特。

GPU 回归除了 GLSL 精积分，还实际运行生产 `froxel_integrate.comp` 并用 `froxel_sample` 读取普通表面：
距离 1–400、相机 far=300、中心／斜射线、全局密度含 0 和 1e-12、全局裁剪与局部盒雾，验证解析 S/T。
完整场景截图与新增路径的 GPU 耗时仍未自动验证。

#### 天空的光学收敛

天空没有有限表面位置，不再拿网格终点冒充天空光程。每 Froxel 列在可见范围以外按指数增长的区间继续
积分，直到残余透过率低于 1e-6；结果写到额外一层，天空片元只双线性读取，不做逐像素长距离步进。
为数值安全，24 个增长区间仍未收敛时使用末端常系数解析延拓至无穷；极弱的无界介质也不会冻结 T。
真空保留 T=1；有限高空层按高度事件分段。这仍是有限采样／远场近似，不宣称精确的无限大气求解。
额外层使累积体积为 `grid.z+2`；积分 pass 同样绑定阴影与局部介质，纹理重载会同步更新它的描述符。

表面照度近似为 `I/max(d²,R²)` 乘距离窗和 Lambert 方向项；
雾中的入射项改为 `L * integral_source_cap(HG dOmega)`，不再把一条 delta 方向的 HG 峰值扩展到近场半球。
HG 在球体立体角内的积分是概率，范围 0..1：轴向／各向同性用解析式，
一般方向在 HG-CDF 坐标下用 8 点正权重求积，远处的小立体角使用点源极限。
这使单灯的相函数加权入射项不超过该灯的辐射亮度；多灯、环境光和背景仍可叠加，不能把此界限误读为最终像素不能超过单灯亮度。

Froxel footprint 会扩大发射体的表观半径，同时按 `I/(pi*R_eff²)` 降低表观 radiance 保持 I，
而不是扩大角范围却维持峰值。阴影和入射介质衰减仍按光源中心近似，并不是精确面积光软阴影或全角度遮挡积分。
8 点求积和远场近似也有误差，不应宣称为任意发射体的精确解析解。

#### 统一曝光和 SDR 显示

真实照明、发射体 radiance 与 Froxel 累积保留线性高动态范围值；**不在密度、源项或每步积分中截到 1**。
反射／散射先按 `R*T+S` 合成，再执行曝光（EV）、亮度 Reinhard 和向中性轴的色域压缩。
自发光改用显示参考算子：旧 `map((R+E)*T+S)` 在 E 为数千倍时，即使 T 很小仍会饱和，
所以“透过率递减”不等于“屏幕上的白点淡出”。设 `m` 是带曝光、映射到 [0,1] 的**线性显示**值：

```
base = m(R*T + S)
glow = m(R + E) - m(R)
display_linear = clamp(base + T*glow, 0, 1)
```

纯灯核 R=0；普通 SurfaceMaterial 的 emission 也走同一算子。显示增量绝对值受 T 约束，
无雾时仍得到原先的 `m(R+E)`。这是一项明确的显示取舍，不是宣称与单次物理 HDR 合成等价；
光源用于照亮表面／介质的 I/R、积分后的 S/T 完全不变。
sRGB 附件由硬件编码；普通 UNORM 附件在 shader 内编码，避免重复 gamma。当前针对常规 sRGB SDR 输出，不是 HDR 显示器 PQ/HLG 管线。
透过率和阴影调试值绕过曝光和 tone curve；散射调试图仍通过显示映射。

当前是无透明混合的不透明场景，线性 HDR 运算在 fragment/float SSBO 中完成，没有额外浮点颜色附件。
若后续加入透明或 bloom，必须重新处理 HDR 附件与显示阶段，不能把这个自发光显示算子当作物理混合规则。
UI 不参与场景曝光。调曝光不使体积历史失效；改 I/R 则会使旧光照历史失效。

可在雾面板关闭「统一 HDR 色调映射」查看反射／散射的原始线性值截白 A/B；默认曝光 EV=0。
自发光显示增量仍限制在 SDR 范围，避免 raw 模式重新引入透雾白点。
雾会把光散射进原本较暗的背景，因而局部变亮本身是合理的，不能要求加雾总是变暗。
无雾时没有体积光晕也是合理的，但发射体不再依赖雾才显示明亮；本轮没有擅自添加 bloom。

屏幕回归先用旧公式复现失败，再验证实际 `display_emissive_surface`：T=1e-6..1、四档发光峰值
（含 I=500/R=.02）、EV=-3/0/3、线性与手工 sRGB 路径、普通自发光材质及无雾外观。
T<=1e-4 时灯体与散射背景差异必须小于一个 8 位显示等级，不再只验证辐射 T 递减。

#### 雾底面与灯表面贴近时的终点积分

这不是时域频闪问题。Froxel 的平均系数不知道雾从格子内部的哪个位置开始：
即使重建了常系数段的部分积分，仍可能把灯块表面之后的高密度雾分配给表面之前的短光程。
调低灯功率或只改灯块材质不能纠正这个边界误差。

开启「近灯表面精细积分（边界纠偏）」（默认开启）时，存在局部雾且片元位于启用的点光
中心 `max(1,R)` 个世界单位内，保留 Froxel 累积前缀，仅在末格与局部雾扩展包围球相交时精细积分到片元；
在 1–2 倍该距离之间平滑切换回网格，避免表面出现硬的球形分界：

- 在盒／椭球的实际进出边界和柔化层内边界处分段，并分开全局 start 与局部介质。
- 加入有限光源核心附近的分段；末段使用 2 段 × 4 次基础采样，另按边界细分。
- 精细积分止于表面，前缀使用网格的双线性结果；接近末格终点时平滑回到缓存值，避免跨格跳变。
- 非均匀缩放时保留变换后方向的长度，确保求交参数仍是世界射线距离。

这个回退专用于局部灯近表面的边界误差，成本高于 Froxel，计入统计面板的 scene+UI 耗时；其他表面和天空继续使用网格。
可关闭该选项作同视角 A/B。它仍是数值积分，不是完整解析解，不支持无限精度薄层或解决全场景的 XY 网格走样；
并未改动原有抖动／历史策略。这个空间误差选项不代替能量约定或显示映射；尚未运行画面和 GPU 性能验证，不能声称所有过曝均已消失。

密度场为世界空间三维平滑噪声叠加；团雾调制整个介质，高空雾用围绕指定高度的高斯层。
动画相位延续已有控制，风的时间尺度随呼吸周期一起变化，不是真实流体模拟。

## 时域复用的细节与限制

- 原始注入采用深度区间内的低差异序列采样并做空间扰乱；局部灯近场使用四个分层样本。
- 关闭抖动或历史无效时固定各分层的中点，避免没有有效累积时直接显示随机噪点。
- 重投影位置取不抖动的体元中心，以历史 view/proj 映射到上一份系数网格，手动三线性读取。
- 历史按交换链图像维护，所以通常不是紧邻上一帧。保存真实相机和时间，权重按间隔帧数指数衰减，年龄超过 1 s 不复用（避免较慢帧率下历史每次都被清空）。
- 首帧、资源重建、天气或场景修改、光照或介质参数变化、投影变化均使历史失效。
- 位移超过 5 个世界单位、朝向点积低于 0.85 时拒绝整份历史；较小运动也会降低权重。
- 视锥外、相机后或超出历史深度范围的体元拒绝历史；超出当前六邻域统计变化范围的密度/散射差异进一步降低权重。
- 历史被裁剪到当前六邻域 min/max 与两倍标准差带的交集，再混合；不再把随机采样导致的单帧亮/暗交替直接认定为光源突变。真实灯光和几何修改仍由 CPU 状态比较/代次立即失效。
- 关闭时域仍运行过滤 pass，但只复制当前数据且关闭随机抖动，便于稳定 A/B 对比。
- 累积局部系数，**不重用旧视线积分**。相函数依然有视角依赖，快速转头时会降低历史贡献，但并不保证零拖影。
- 当前不保存表面深度历史：完整视锥中的介质一直有效，不以物体深度截断系数场。几何遮挡改变由阴影变化拒绝与邻域裁剪处理，薄小遮挡仍可能闪烁或漏光。
- 没有运动矢量、风场反向平流或逐灯历史分类；不能当作通用高动态场景 TAA 去噪器。

## 资源成本与质量控制

### ECS 局部介质

局部雾由普通 ECS 实体表达，不依赖 Renderable：

- `Transform`：平移、四元数旋转、非均匀缩放。局部盒范围 `[-0.5,0.5]³`，椭球局部半径 0.5，因此 scale 是完整尺寸／直径，不是半径。
- `FogVolume`：shape（0 盒／1 椭球）、density（附加消光）、color、albedo、edge_fade（相对半径的边缘过渡宽度）、enabled。
- 可选 `FogDensityTexture`：path、extent、tiling、offset、strength、repeat。没有组件、空路径或 strength=0 时为均匀介质。
- 可选 `FogControlField`：启用时替代纹理密度来源，由归一化控制点与多尺度梯度噪声生成密度；材质和外边界仍由 `FogVolume` 决定。
- 建议附加 `Tag` 以便在检查器显示；渲染系统查询 Transform+FogVolume，不要求 Tag，也不要求几何。

UI 可以添加盒形雾或带 `builtin:cloud` 的椭球雾；参数在检查器编辑。勾掉 enabled 可停用；
程序中也可以用 ECS 添加／移除组件。UI 支持复制／删除雾实体；纹理路径和原始尺寸通过场景数据或代码设置。
场景 `fog_volumes` 为可选数组，旧 scene.json 不必修改；完整片段见 `local-fog.example.json`。
每项 tag/pos/scale 必填，其余字段有默认值；texture 若出现，path 必填。

也可直接在 C++ 场景代码中创建，不需要手工操作 GPU 资源：

```cpp
fog::FogVolumeEntity cloud(em, "local-cloud",
    fog::FogVolume{ .shape = 1, .density = 0.25f },
    fog::FogDensityTexture{ .path = "builtin:cloud" },
    glm::vec3(0.0f, 3.0f, 0.0f), glm::vec3(8.0f, 4.0f, 8.0f));
```

介质叠加使用 `sigma_t_total = sigma_t_global + sum(sigma_t_local)`、
`sigma_s_rgb_total = sigma_s_rgb_global + sum(sigma_t_local * color * albedo)`。
不会按数量平均颜色，也不会让最后一个实体覆盖前面的介质；几何光照的入射光衰减亦使用总消光。
当前所有介质共用全局 HG 参数 g，不支持每体积独立相函数或 RGB 吸收。
有局部雾时，其近端不受全局 start 限制；仅显式开启艺术裁剪时，start 在注入时单独对全局介质采样门控，
边界存在一个体元内的分层近似。表面积分覆盖全部可见光程，天空延拓也查询局部雾，不再由旧 end 截断。

#### 3D 密度资源

`builtin:cloud` 是确定性的程序化体数据；也可以提供无文件头的 raw R8 文件，例如：

```json
"texture": {
    "path": "fog/density/cloud.raw",
    "extent": [64, 64, 64],
    "tiling": [1.0, 1.0, 1.0],
    "offset": [0.0, 0.0, 0.0],
    "strength": 1.0,
    "repeat": false
}
```

相对路径从 assets 工作目录解析；文件必须恰好 `width*height*depth` 字节，X 最快、Y 其次、Z 最慢，
0=无密度，255=满密度，各轴支持 1–128。输入经 CPU 三线性重采样到 32³，不能保留 128³ 的全部细节。
最多 4 种不同路径+尺寸；共享纹理不会重复占槽。关闭但仍挂载纹理组件的实体也保留其资源槽。

GPU 为真实 `VK_IMAGE_TYPE_3D / R8_UNORM / sampler3D`，每槽带保护边，槽内三线性采样；
UV 映射到体素中心范围，避免相邻资源串色。重复使用 fract UV，输入应是可平铺的数据；非周期数据在接缝处仍可能不连续。
没有 mipmap、纹理热监测或体素压缩。可以用「重载局部雾 3D 纹理」重新读取修改过的 raw 文件。
路径/尺寸集合改变时等待 GPU 空闲并重建图集和描述符；只改密度、形状、颜色、UV 或变换时无需重建纹理。

每图像独立上传局部参数 SSBO，读写受 acquire 的 image fence 保护。实体或资源内容变化会使体积历史失效；
变换动画频繁修改时优先正确性，暂不做局部体积运动矢量补偿。退化的变换不注入，超过数量上限明确报错，不静默截断。
此版本对射线段与局部体积扩展包围球相交的体元使用四层注入采样，而不是让整个网格统一四倍开销。
小于体元的薄雾或高频纹理仍可能欠采样，应增加切片／缩小像素步长。

此图集约 154 KiB，共享于所有交换链图像；每图像附加 2832-byte 参数缓冲。
统计面板计入 Froxel 与新增控制场缓存，不包含旧图集及该局部参数缓冲。

#### 控制点密度场

`FogControlField` 最多含 32 个 `FogControlPoint`，每点的位置为局部 `[0,1]³`；
转换到原有体积局部空间只需减去 0.5，旋转与非均匀缩放由 `Transform` 统一处理。
点的半径 `[0.02,1]`、密度 `[0,4]` 和柔和度 `[0.05,1]` 定义紧支撑的平滑雾团。
相加后采用 `1-exp(-sum)` 平滑限制密度，再由 1–5 层梯度噪声调制；噪声强度为零时完全关闭噪声。
64³ 网格无法表达的高频 octave 会衰减，避免把走样写入缓存。实际消光仍乘 `FogVolume.density` 与外边缘衰减。

运动采用每场独立的归一化周期 `cycle`，只由世界 tick 推进；暂停／单步沿用全局动画控制。
每点的频率为 1–8 的整数，轨道幅度按初始位置到边界的余量收紧，避免硬裁剪坐标。
噪声位移也沿闭合轨道，因此一个完整 period 后密度场回到原始循环相位。
关闭单个场的 animated 时显示原始点位；再次启用会继续保留的运行期周期。保存只记录用户参数，不记录 cycle。
这是程序化循环，不是流体、湍流输运或气体模拟。

每个交换链图像独占控制参数 SSBO（binding 12）及密度网格 SSBO（binding 11）。
每槽 64³ 个 float，预留 16 槽共 16 MiB，另有 17152-byte 控制参数。
生成 pass 的 push constant 选择槽位，只重建控制数据发生变化的活动槽；静态场首次为各图像生成后复用。
参数上传在 acquire 对应图像 fence 完成后进行；生成后显式 compute-write → compute/fragment-read 屏障。
只有成功提交／呈现才标记缓存代次，失败时让全部图像的生成缓存失效。图像重建时一起重建资源。
采样使用手动三线性，表面、光路衰减、体元注入和天空使用同一密度查询。
动画不会每帧递增全局 history epoch，沿用现有时域响应；用户编辑和实体改动仍使历史失效。
短周期或快速运动仍可能出现时域拖影，可关闭历史累积对比。

存档 schema 是可选 `control_field`，旧文件默认 disabled；开启时覆盖而非乘上旧纹理。
控制点字段全部写入存档，允许零点（空场）；样例见 `control-fog.example.json`。
新增 GPU 生成与编辑回归入口尚未实际运行，以上为实现说明，不是性能或画面验收结论。

### Froxel 缓冲

每个体积元素为四个 32-bit 浮点数，继续使用 SSBO，不声称是硬件 3D 纹理。
若列数为 X×Y、深度为 Z，每个交换链图像的体积逻辑存储为：

```text
16 * X * Y * (4 * Z + 2) bytes
  = raw injection + two coefficient histories + integrated volume (extra near boundary)
```

统计面板显示以上大小加控制场网格／参数的大小和乘以交换链图像数后的总量，**不包括** Vulkan 分配粒度、阴影、深度、纹理和驱动内部开销。
默认屏幕步长 8、Z=64，XY 上限 192×128，Z 可调 16–96；桌面高质量时显存成本仍显著。
阴影额外占用每图像 `2048² + 1024²` 个深度元素，使用 D32，若不支持则退回 D16。

没有跳帧更新：本轮暂不考虑移动端，因此优先每帧刷新密度与光照，并提供独立空间质量控制。

### 视觉 A/B

1. 固定相机，依次选择浓雾、团雾、高空层雾，记录完整合成、透过率、散射图。
2. 开关阴影，观察房屋、树和模型的表面阴影与雾内遮挡是否同步；调低环境光或降低太阳，单独观察火把/灯笼的局部光。
3. 移动点光到墙体一侧，验证墙体能截断 cube shadow；检查模型轮廓，不接受仅 AABB 形状的遮挡。
4. 相机缓慢平移、快速转身、穿越雾层；比较时域开/关、抖动开/关的噪声、稳定性和拖影。
5. 切换天气、光源位置和密度，验证历史不会保留旧颜色或光束；缩放窗口和修改切片，验证无未初始化闪烁。
6. 密度和近地密度均置零，验证 T≈1、散射≈0；关闭反照率时应只有吸收，没有新增散射。
7. 检查太阳覆盖区边缘、聚光锥边缘、细枝和灯具近端；记录 bias 引起的痤疮与悬浮阴影。
8. 固定点光功率，沿同一观察方向前后移动相机，比较 32/64/96 切片及抖动开关；重点检查灯附近的白球、跨格亮度跳变与光束边缘噪点。

### 性能记录

- 固定分辨率、相机、天气、光源参数，先预热至少 120 帧；每档采集至少 300 帧。
- 对比 `(pixel step, slices)`：`(16,32)`、`(8,64)`、`(4,96)`，记录实际网格是否达到 XY 上限。
- 对比时域开/关、阴影开/关、入射光步数 0/4/8；保持其他条件相同。
- 记录 GPU/驱动、分辨率、交换链图像数、网格大小、体积逻辑显存、GPU 各阶段时间，以及离线统计的中位数/P95。
