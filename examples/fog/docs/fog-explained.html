00一页速览先建立骨架

每条相机射线穿过介质时，背景光按 Beer–Lambert 指数衰减，同时介质把太阳、天空和灯的光 散射进这条射线。Froxel 体积雾不是“在画面上刷一层灰色”，而是把这条连续积分拆成： 空间离散（注入系数） → 时间去噪（历史复用） → 沿深度前缀积分（integrate）， 片元阶段只重建射线位置并查表。

整条链路只有一个目标：算出这条射线的 S 和 T
τ = ∫ σt(p) ds   ·   T = e−τ   ·   S = ∫ T(s) · σs(p) · Lin(p, ω) ds
最终像素 = background · T + S（背景先被吸收，再叠加上沿途散射进来的光）

代码里把 σs·Lin 合称“源项”，存进 froxel 的 RGB； 把 σt 存在 A 通道。于是每个格子就是一个 vec4(scatter.rgb, extinction)。 integrate 阶段沿列做的是前缀积分：第 z 层存的是“从相机到第 z 个边界”的累积 S/T， 所以片元只要按自己的深度插值一次，就能得到“到它为止”的雾。

三个必须记住的近似

  • 每格常系数：一个体元内 σ、源项视为常数，用中点采样代表；误差靠抖动、4 层采样和历史来压。
  • 单次散射：光只从光源直接进入介质，没有“雾被别处雾照亮”的多次散射。
  • XY 分辨率有限：相邻像素共享一列，薄物体边缘、细光束会被体元 footprint 抹宽。

这三点决定了所有“看起来不对”的现象该往哪里查：格子走样、缺多次散射、还是时域拖影。

01辐射传输与 Beer–Lambert物理层

先把“雾”翻译成两个可测的量：消光系数 σt（每走一米，光被吸收/散射掉多少比例）和 源项 q（每走一米，有多少光被散射进这条视线）。之后所有 GPU 代码都只是在求这两个量的积分。

1.1 从吸光度到光学厚度

均匀介质的实验规律是吸光度 A 与浓度、光程成正比：

Beer–Lambert 定律
A = log10(I0/I) = ε · c · l   ⟹   I/I0 = 10−A = e−A ln 10
令 σ ≡ ε c ln 10（单位 1/长度），就得到 T = e−σ l；σ 就是代码里的“密度”。

介质不均匀时，把路径切成无穷小段：每段的透过率相乘，取极限就变成指数相加。定义无量纲的 光学厚度 τ：

沿一条世界空间射线的积分
τ = ∫0d σt(p(s)) ds   ,   T = e−τ ∈ (0, 1]

σt 同时包含吸收和外散射（光被弹到别的方向，离开这条视线）。代码把它存成 RGB 系数里的 A 通道； RGB 三个通道则存散射系数乘上光照后的源项，因此可以做带颜色的雾，而消光仍是标量。

1.2 体积渲染方程：光如何被“加”回来

只看一条射线时，辐射亮度 L 沿路径的变化是“损失 − 新增”：

Radiative Transfer Equation（单次散射形式）
dL(p, ω)/ds = −σt(p) L(p, ω) + σs(p) ∫S² p(ω·ω′) Li(p, ω′) dω′ + Le

这个例子里没有自发光介质，也没有多次散射。光源只有太阳（方向光）和有限的点光，所以积分项被压成 “相函数 × 入射光”的求和：

代码里实际求的源项
q(p, ω) = σs(p) · [ Lambient + pHG(ω·ωsun) · Esun · Vsun + Σlights Lemitter · Pcap ]

其中 σs = σt · albedo · fog_color（代码里 medium.rgb）， V 是阴影与介质衰减，Pcap 是相函数在有限发射体立体角上的积分（第 04 节）。 环境光被当作各向同性的常量，所以不乘相函数——这是一项刻意的近似。

1.3 一格常数：解析解而不是“乘个 exp”

注入阶段把每个体元内的 σ 和 q 当成常数。对长度 Δ 的一小段，从 a 到 b 的解可以直接积出来：

常系数段的解析积分
L(b) = L(a) · e−σtΔ + q · (1 − e−σtΔ) / σt
记 Tseg = e−τ，τ = σtΔ，则新增项 = q · (1 − Tseg) / σt

推导：把 q 当常数，∫0Δ e−σ(Δ−s) q ds = q e−σΔ(eσΔ−1)/σ = q(1−e−σΔ)/σ。 注意 (1−T)/σ 是“这段的等效长度”，不是 Δ——浓雾里只有靠近相机的一小截真正可见。

σ → 0 时这个式子会 0/0。代码用一阶展开兜底：当 τ < 0.001 时取 Δ·(1 − τ/2)；一般项则直接把 τ 截到 80（e−80 ≈ 1.8×10−35， 再大对 32 位浮点已无意义，也避免 exp 溢出）。这套写法在 froxel_integrate.comp、fog_integrate_interval() 和 CPU 回归里是同一份。

沿一列的前缀递推（integrate pass 的核心）
Si+1 = Si + Ti · qi · (1 − Tseg,i)/σi   ;   Ti+1 = Ti · Tseg,i
顺序很重要：新增项要用这一格之前的 Ti 加权，之后才更新 T。

最后把背景（几何着色结果或天空）和被积出来的 S 合成。背景不参与“雾色平均”，它只是被 T 衰减：

最终合成
Cout = Cbackground · T + S

这解释了一个常见直觉错误：加雾不一定是“变暗”。雾会把光散射进暗背景，S 可以大于 Cbackground(1−T)，所以浓雾中的灯周围会变亮。

02Froxel：把视锥切成立体网格空间离散

“Froxel” = frustum + voxel。它不是世界空间的三维纹理，而是贴着相机视锥的一叠格子： 屏幕每 8×8 像素共用一列，深度方向再切 64 层。这样相邻像素共享密度和光照计算， 成本从“像素 × 步数 × 光源”降到“格子数 × 光源”，而代价是空间分辨率有限。

2.1 为什么不用逐像素步进

方案优点在本场景的代价
解析高度雾（旧版）闭式解，几乎零成本只有高度分层，做不出三维雾团、局部灯光束和遮挡
逐像素 raymarch直观、可精确停在表面1080p × 48 步 × 每步光照 ≈ 每帧上亿次采样，且相邻像素重复算同一段空气
Froxel多像素共享；空间/深度分辨率可独立调；可做时域复用额外显存；边缘与近场有体元走样
光追体积遮挡、多次散射更完整采样与去噪成本高，不适合这个桌面示例

关键洞察是：空气的密度和光照在屏幕空间上是低频的。同一面墙上的 8×8 个像素， 它们前方几米内的雾几乎一样，没必要各算一遍。真正需要高分辨率的是几何边缘， 而那是深度测试和表面积分要解决的问题，不是体积网格。

2.2 网格尺寸与上限

CPU 每帧按窗口大小算一次网格（app_setup.cpp）： 

grid_x = clamp(ceil(width  / pixel_size), 1, 192)
grid_y = clamp(ceil(height / pixel_size), 1, 128)
froxel_depth = clamp(depth_slices, 16, 96)   // 默认 64

192×128 是硬上限，目的是把最坏情况的显存与 compute 时间钉住。1280×720、8 像素一格时是 160×90； 1920×1080 想要 240×135，会被截到 192×128——此时一格实际覆盖约 10×8.4 个屏幕像素， 而不是配置里的 8×8。这是“上限”而不是“会自动加密”。

每个格子存一个 vec4：RGB = 已乘光照的散射源项，A = 消光。每个交换链图像独占 原始注入、双缓冲历史、积分结果，逻辑大小是：

每张交换链图像的体积显存（不含分配粒度）
16 · X · Y · (4Z + 2) 字节  =  injection(Z) + history(2Z) + integrated(Z+2)
192×128×64 → 16·192·128·258 ≈ 96.75 MiB；160×90×64 → 约 56.7 MiB

2.3 深度切片：为什么是对数

如果深度均匀切 64 层、far = 300，那么每层厚 4.7 米。可相机前方 0–5 米内集中了大部分可见细节、 灯核和表面边界，4.7 米的格子会把整盏灯抹成一团；而 100 米外每层 4.7 米又完全够用。 所以网格在视深度 z 上按几何级数分布：

切片边界（fog_common.glsl · froxel_depth_at）
d(z) = W · ( eln(1 + far/W) · z/Z − 1 ),   z ∈ [0, Z]
等价地：d(z) + W = W · rz，相邻边界比 r = (1 + far/W)1/Z

推导很直接：希望 (d+W) 每层乘同一个比例 r，且第 Z 层正好到 far。 于是 rZ = 1 + far/W，解出 r，再反解 d(z)。加 W 是为了让 z=0 时 d=0， 同时避免 ln(0)。本实现取 W = 1（UBO 里 froxel_grid.w）。 默认 far=300、Z=64 时 r ≈ 1.0932：第 1 层厚约 0.093 米，最后一层厚约 25.7 米， 相邻层厚度之比恒为 1.0932。近处极细、远处按比例变粗，正好匹配透视。

采样时用的是反函数（froxel_sample.glsl）： z = Z · ln(1 + d/W) / ln(1 + far/W)。注意这里的 d 是视深度 （相机空间 −Z），不是沿射线的距离。

斜射线修正（很关键，漏了就会出现屏幕边缘变清）
cos θ = max(−(view · ray).z, 10−4)   ,   世界光程 = 视深度 / cos θ

一个体元的厚度是“沿相机 Z 轴”量的，但光线以角度 θ 穿过它时，实际走的世界距离是 Δz / cos θ。integrate 里用 span = d(z+1)/cos − d(z)/cos 才是真正的光程。 如果错误地直接用 Δz，画面四角的光学厚度会少一个 cosθ 因子，表现为“中间雾浓、边缘雾薄”。

2.5 成本：分辨率的三次方很贵

compute 的线程数是 X·Y·Z。默认 192×128×64 = 157 万个格子，注入阶段每格至少 1 次密度与光照采样； 局部雾或近灯格子会用 4 个分层样本。相比之下 integrate 只有 X·Y = 2.46 万列， 每列 64 步主要是算术（只有天空延拓会再采样密度）。注入的线程数和光照采样更多，通常更重； 实际占比要看统计面板的分段 GPU timestamp，不能只按线程数断言。

质量档位（性能/均衡/精细）就是把这几个数一起改：像素步长 16/8/4、切片 32/64/96、 入射光步数 2/4/8。注意改网格会等待 GPU 空闲并重建资源， 不是每帧都能改的滑杆；而改密度、光照参数只是更新 UBO。

03密度场：天气、噪声与呼吸介质定义

密度不是一个全局常量，而是世界坐标的三维函数。它由三层叠成：全空间基础密度 + 贴地指数雾 + 三维值噪声，再乘一个随时间缓慢起伏的 呼吸/行波因子。天气预设只是把这几个数换一组。

3.1 逐点密度函数

fog_common.glsl · fog_global_density
σmist(p) = σmist0 · exp(−k · max(py − ground, 0)) · N(p)
σ(p) = max( [ σbase + σmist(p) ] · anim(p, φ), 0 )

注意 max(p.y − ground, 0)：参考面以下不继续增大，雾在海平面以下是“满”的， 不会随着往下走指数爆炸。指数项的 e 折高度是 1/k 个世界单位—— k=0.25 时大约每升高 4 米衰减到 37%。σbase 则与高度无关， 所以站到高空仍然会按距离吃雾。

天气编号会改写这个式子（weather 存在 fog_shape.x）：

weather行为公式变化
1 浓雾基础项主导，噪声弱，缓慢呼吸原式；σbase=0.10、σmist=0.035、k=0.25
2 团雾噪声调制整个介质，形成明暗斑块σ *= smoothstep(0.30, 1.20, N) * 2
3 高空层雾围绕某一高度的薄层，像云海σ = (σbase+σmist) · exp(−½h²) · N，h=(y−center)/thickness
0 自定义保留当前所有参数不做任何覆盖

团雾那一行值得注意：σmist 里已经乘过一次 N，外面又乘 smoothstep(0.3,1.2,N)·2，所以低噪声区被压到接近 0、高噪声区被放大， 斑块对比比“单纯把噪声幅度调大”更强。高空层则完全替换原式，连基础项也限制在薄层里。

3.2 三维噪声是怎么省出来的

这里没有 3D 噪声纹理，而是用两层 2D 值噪声按 z 混合，再叠一层交叉采样： 

vec3 q = p * noise_scale + vec3(0.8, 0.1, 0.35) * phi * wind_speed;
float z = floor(q.z), f = smooth(fract(q.z));
float n = mix( valueNoise2(q.xy + z * vec2(19.1, 7.7)),
               valueNoise2(q.xy + (z+1) * vec2(19.1, 7.7)), f );
n = 0.7 * n + 0.3 * valueNoise2(q.xz * 2.7 + q.y * 0.3 + 13.1);
return mix(1.0, n * 2.0, noise_amount);
  • 值噪声：格点哈希 → 双三次平滑插值。两层 2D 采样等价于一个轴向切片的三维场，成本只有 2 次 2D 噪声。
  • 0.7 / 0.3 交叉项：第二层用 xz 平面并混入 y，打破第一层在 z 方向的层状感。
  • mix(1, 2n, amount)：n 的均值约 0.5，所以 2n 均值约 1。amount=0 时完全关闭噪声，amount=1 时密度在 0–2 倍之间起伏。
  • 世界空间平铺：坐标直接取世界位置，不随相机移动，所以雾团是“钉在岛上”的，相机穿过去不会像贴屏后处理一样跟着滑。

vec3(0.8, 0.1, 0.35) * phi * wind_speed 是平流项：噪声场随相位缓慢漂移。 它不是流体模拟，没有速度场、涡量或质量守恒；只是让同一块噪声平移， 再靠呼吸项改变整体浓度。

3.3 时间项：为什么用三个无理频率

fog_anim_factor（φ 由 CPU 按周期累加）
breath(φ) = 0.50 sin(φ) + 0.30 sin(1.2720196 φ + 1.7) + 0.20 sin(1.6180340 φ + 0.4)
wave(p,φ) = sin( k·pxz · 2πf − 1.2720196 φ + 0.45 sin( kyx·pxz · 2πf · 0.59 + 1.09 φ ) )
anim = max(0, 1 + amp · [ 0.55 · breath + 0.45 · wave ])

频率比取 1 : √φ : φ ≈ 1 : 1.2720 : 1.6180（φ 是黄金比例）。 这三个频率彼此接近、又不是整数比，所以：

  • 没有短的公共周期，肉眼很难抓到“又循环了”；拍频在分钟量级。默认周期 60 秒时，三个分量约 60 / 47.2 / 37.1 秒，两两拍频约 3–5 分钟。
  • 三个振幅 0.5 / 0.3 / 0.2 刻意接近，避免被单一低频主导成明显的“呼吸节拍”。
  • 行波只在 xz 平面传播（雾团水平翻滚），相位里再套一层慢波，让波峰波谷自己被调制。

04光照、相函数与阴影源项从哪来

密度只决定“有多少介质”，真正让雾可见的是被散射进视线的光。这一节把太阳、天空环境光和 火把/灯笼点光变成注入阶段的 RGB 源项，并解释相函数、有限发射体和阴影的近似。

4.1 源项：反照率与相函数

注入阶段每个采样点的源项
q(p, ω) = σt(p) · albedo · Cfog · [ Lamb + pHG(μsun) Esun Vsun + Σi Li Pcap,i ]

albedo（默认 0.9）是“被消的光里有多少被散射而不是被吸收”。它只影响散射颜色， 不影响透过率——把 albedo 调到 0，雾仍然会挡住背景，只是不会把光加回来，画面会变暗。 Cfog 是雾色，乘在 RGB 上，因此雾可以有颜色而消光保持标量。

4.2 Henyey–Greenstein 相函数

finite_light.glsl · phase_hg
p(μ) = (1 − g²) / ( 4π (1 + g² − 2gμ)3/2 ),   μ = cos θ   ⟹   ∮ p dω = 1

μ 是“视线方向”与“指向光源方向”的夹角的余弦。g > 0 表示前向散射： 光更容易继续沿原方向传播，所以看向太阳时雾最亮（μ→1），背对太阳时暗。 这是雾中太阳周围出现光晕、而背光方向发灰的原因。g = 0 退化为各向同性 1/4π； |g| 越接近 1，峰越窄。代码把它夹在 ±0.85，默认 0.45。

归一化很重要：p 在整个球面上的积分是 1，所以它有“概率密度”的量纲（1/sr）。 若忘了 1/4π，光源亮度会整体放大 4π 倍；若把一条 delta 方向上的 p 峰值直接当成 近场半球的光照，近距离会亮得离谱——这正是 4.4 要解决的。

太阳阴影的工程细节：

  • 2048² 正交深度图，中心固定在岛屿 (0, 8, 0)、覆盖半径 sun_extent = 48。不跟随相机，避免相机移动导致投影抖动。
  • 方向或几何变化时才重绘；每张交换链图像各缓存一份，避免多帧同时读写。
  • 覆盖区外按“可见”处理——它不是无限世界阴影，远处地形没有太阳阴影是预期行为。
  • PCF：体积里 3×3，表面 5×5；bias=0.001，表面另加 normal_bias=0.035 的沿法线偏移。
  • 水面是独立半透明批次，不写深度、不进入 shadow pass；自发光灯核也不投影，避免灯被自己挡住。

4.4 点光：有限半径发射体，而不是数学点

火把和灯笼是半径 R ≈ 0.11 的球形发光体，强度 I 对应表面辐射亮度 L = I / (πR²)。这个式子来自朗伯圆盘/球体的投影面积 πR²：总光通量与亮度、 投影面积成正比。把它放到距离 d 的采样点，立体角约 Ω ≈ πR²/d²，于是单次散射项：

有限发射体的内散射（远场极限）
qlight ≈ σs · L · p(μ) · Ω = σs · [I/(πR²)] · p(μ) · [πR²/d²] = σs · I · p(μ) / d²

这正好是“平方反比 × 相函数”，不需要额外的 1/d² 手工项。代码保留 R 是为了两件事： 近场（d 与 R 同量级）时不能用远场极限，以及可见灯体的亮度要与照明一致。

近场为什么不能直接用 p(μ)

d 很小时，发射体张开的立体角很大，p(μ) 在球面上变化剧烈；用中心方向的一个采样会高估或低估， 甚至在灯附近产生“白球”。finite_light.glsl 改为对发射体覆盖的球冠积分：

  • 把 p(μ) 转成 HG 的 CDF 坐标，先算出球冠对应的 CDF 区间 [lo, hi]；
  • 在区间内用 8 点 Gauss–Legendre 求积，再乘上方位角占比；
  • 结果被 clamp 到 [0,1]，表示“这颗灯打到这个方向的概率”，因此不会超过灯的辐射亮度；
  • 球冠极小时退回点源极限 p(μ)·2π(1−cosθ)，数值稳定。

另外，体元横向尺寸 footprint 会合并进有效半径： Reff² = R² + footprint²，同时亮度改成 I/(πReff²)， 保持总强度 I 不变。这样远处粗格子里的灯不会变成一个闪烁的单像素白点，而是被正确地“抹宽变暗”。

距离窗、阴影与光源裁剪

  • 距离窗 w = clamp(1 − (d/range)4, 0, 1)²，在 range 处平滑归零；衰减用 w / max(d², R²)，避免 d→0 的奇点。
  • 点光 cube shadow：6 个 90° 面写入 512² 深度图集，每帧只取离相机最近的 5 盏；面方向与 CUBE_DIR/CUBE_UP 表一一对应。
  • 深度比较是手写的：把距离重建成与渲染时相同的 RH_ZO NDC，再和存储深度比较（不使用硬件 cube compare sampler）。
  • light_cull.comp 为每个 froxel 生成 8 位掩码：只有范围球与格子相交的灯才进入注入循环。灯多时省的是“每格 × 全部灯”的无效遍历。
  • 灯核是均匀自发光（材质 voxel=−1），不接受自身点光或太阳的表面照明；可见亮度只由 I/R 与显示算子决定，不会被自己照亮成黑球或叠加额外高光。
能量约定：I 和 R 同时决定“看起来多亮”“照亮表面多强”“雾里散射多强”，三者不再各用一个魔法常数。 这些仍是相对场景单位，不是标定过的流明/瓦特。灯核在显示阶段还有单独的自发光算子，见 06 节。
没有做的事：多次散射、CSM（级联阴影）、水下折射、透明材质投阴影、面积光软阴影积分、逐体积独立相函数。 “雾里所有东西都亮了一点”是单次散射 + 环境光的近似结果，不是全局光照。

05三阶段 compute：注入 → 时域 → 积分GPU 实现

每帧在渲染作用域之外录三段 compute。它们的分工不是“各算一部分”，而是 先把介质属性写进格子，再把格子沿深度积成前缀。顺序不能换：积分结果依赖过滤后的系数， 过滤后的系数依赖本帧注入，注入依赖本帧阴影。 

injection  (Z × XY × vec4)   σ_s·L_in.rgb , σ_t
      │  compute write → compute read barrier
temporal   (Z × XY × vec4)   与历史重投影混合、邻域裁剪
      │  compute write → compute read barrier
integrate  (Z+2 × XY × vec4) 每列前缀 S/T + 天空收敛层
      │  compute write → fragment read barrier
scene / sky fragment         三线性查表 + 局部段重建

5.1 注入：每个格子采样一次介质

froxel.comp 用 4×4×4 的 workgroup，一个 invocation 对应一个格子。它先由格子中心的 uv 反投影出一条世界射线，再算出这一格的起止径向距离： 

vec3  ray   = froxel_ray((vec2(p.xy) + 0.5) / grid.xy);
float cosθ  = max(-(view * vec4(ray, 0)).z, 1e-4);
float a     = froxel_depth_at(p.z)     / cosθ;
float b     = froxel_depth_at(p.z + 1) / cosθ;
vec3  mid   = camera + ray * (a + b) * 0.5;
float footprint = center_depth * length(1.0 / (grid.xy * vec2(proj[0][0], proj[1][1])));

footprint 是该深度上一个体元的横向尺寸（用于光源过滤和抗锯齿，不是格子体积）。 然后决定这一格要采几个点：

  • 默认 1 个样本，取分层随机位置 t = (0 + jitter)/1；
  • 如果格子落在某盏点光的近场、与局部雾包围球相交、或跨过可选的全局近端裁剪面，就升到 4 个分层样本，避免近场的陡梯度被一格平均掉；
  • 抖动值 fract(frame·0.618 + hash(cell)) 是黄金比例序列 + 空间哈希，低差异且相邻帧不相关；时域无效时强制取 0.5，保证没有历史时也不会满屏噪点。

每个样本调用 fog_medium(world) 得到 vec4(σ_s.rgb, σ_t)，再乘 volume_illumination_masked() 得到源项。如果 RGB 全为 0（纯吸收介质），就跳过阴影采样、 光路步进和相函数积分，只保留消光项——这是很实用的一处提前退出。最后 4 个样本取平均写入 injection。

5.2 时域：复用“系数”，不是复用“积分结果”

抖动采样会带来噪点。最直接的去噪是时间累积：把当前格子和历史帧里对应位置混合。 但这里累积的是局部散射系数和消光，不是已经沿相机射线积好的 S/T。原因是：

  • S/T 依赖相机位置、方向和相函数；相机一转，旧射线的积分就不代表新射线。
  • 系数是介质本身的局部属性，只要世界位置对上，换视角仍然有效；积分留到本帧重新做。

CPU 每帧先判断历史能不能用（app_systems.cpp）：

年龄 ≤ 1.0 s  &&  相机位移 < 5 世界单位  &&  朝向点积 > 0.85
&& UBO 关键状态完全一致（网格、雾参数、光照、体积参数……）

通过后历史权重为 w = 0.9age · e−0.4·距离 · alignment8， 并夹到 0.97 以下。也就是说：停着不动时几乎全用历史；快速平移或转头时迅速退回本帧。 history_epoch 一旦因天气、光源、局部雾或资源重建而改变，整份历史立即作废。

GPU 侧的重投影与拒绝（froxel_temporal.comp）：

  1. 用不抖动的格心世界位置，乘上一帧的 view-projection，得到上一帧 uv 与视深度；
  2. 在相机后、视锥外、深度超过 far 的格子直接放弃历史；
  3. 把旧位置换算成历史网格坐标，手动三线性读取 8 个邻居；
  4. 取当前格子 + 6 个面邻居的 min / max / 均值 / 二阶矩，得到局部标准差 σn；
  5. 若历史与局部均值的差超过 2σn，按超出量算出 response 降低权重—— 这样“抖动导致的光束边缘一亮一暗”不会被误判成光源突变；
  6. 把历史夹到 [max(lo, mean−2σ), min(hi, mean+2σ)] 后再混合。
最终过滤
filtered = mix(current, clamp(old), clamp(w · response, 0, 0.97))

一个容易忽略的点：历史按交换链图像维护，所以“上一帧”通常不是紧邻帧（三缓冲时可能隔 2–3 帧）。 权重按实际帧龄指数衰减，避免低帧率下历史刚写入就过期。没有运动矢量、没有深度历史， 因此快速移动的薄遮挡仍可能闪烁或漏光；这不是通用 TAA。

5.3 积分：每一列做一次前缀和

froxel_integrate.comp 的线程数只有 XY（8×8 workgroup），每个线程负责一条屏幕列： 

S = 0; T = 1;                        // 相机处
volume[column] = vec4(S, T);        // 第 0 个边界
for z in 0..Z-1:
    next = froxel_depth_at(z+1) / cosθ
    span = max(next, start) - max(prev, start)
    σ    = filtered[z, column].a
    τ    = min(σ · span, 80)
    Tseg = exp(-τ)
    integral = τ < 0.001 ? span·(1-τ/2) : (1-Tseg)/σ
    S += T · filtered[z, column].rgb · integral
    T *= Tseg
    volume[z+1, column] = vec4(S, T)

start 默认是 0（物理模式），只有显式勾选“全局近端裁剪”才从 fog.start 起算。 有局部雾时积分仍从 0 开始，只在注入时对全局分量做门控，局部雾永远保留近场。 循环结束后还有一层“天空层”：

天空没有有限表面，不能让网格终点冒充无限远
从 far 之后继续以 Δ = max(far/8, 1) 起步、每段翻倍，最多 24 段，直到 T < 10−6； 仍未收敛则用末点的常系数解析延拓到无穷。

这一层每列只算一次，存到 volume[Z+1]。天空片元只做双线性采样，不逐像素做长距离步进。 对于“高空层雾”这种有限厚度介质，积分还会在若干高度事件处切段，避免倍增区间直接跨过薄层。

06片元采样、合成与显示最后一步

片元拿到世界坐标后，要回答三个问题：我的位置落在哪个格子？ 我和格子边界之间还有多少介质？ 结果怎么映射到屏幕？ 前两个问题决定了雾在物体表面、灯核附近是否“贴得住”。

6.1 先定位：uv → 列，深度 → 切片

clip  = proj * view * vec4(world, 1);
uv    = clip.xy / clip.w * 0.5 + 0.5;
depth = max(-(view * vec4(world, 1)).z, 0);      // 视深度
slice = log(1 + min(depth, far)/W) / log(1 + far/W) * Z;
slice = clamp(slice, 0, Z - 0.0001);

vec3 cell = vec3(uv * grid.xy - 0.5, slice);      // 格子索引空间
ivec3 b = ivec3(floor(cell));  vec3 f = fract(cell);
lower = bilinear(b.xy,   b.z);                    // 第 b.z 个边界
upper = bilinear(b.xy,   b.z + 1);                // 第 b.z+1 个边界

注意 uv * grid - 0.5：格子中心在 (i+0.5)/X，减 0.5 后才能用 floor/fract 做标准的双线性权重。XY 是双线性（4 次 fetch）， 深度方向不是简单 lerp 两个已积分值——那是下一节的关键。

6.2 部分段重建：S 不能线性插值

integrate 只在边界存了 (S, T)。如果表面落在第 z 和 z+1 个边界之间，直接 mix(Sz, Sz+1, f) 是错的：S 随距离是指数收敛的，不是直线。 正确做法是只用这两个边界反推出这一格的常系数，再对表面之前的局部段单独积分。

从两个边界反推
step_T = Tz+1 / Tz = e−τ   ⟹   τ = −ln(step_T)
partial_T = e−τ·f，  f = clamp( (dsurface − a) / (b − a), 0, 1 )
局部新增 = q·(1 − e−τf)/σ   ⟹   scatter_fraction = (1 − partial_T) / (1 − step_T)

最后一行是两段积分的比值：整格的新增是 (1−step_T)/σ，前 f 段是 (1−partial_T)/σ，相除就得到“这一格的新增量里，前 f 段占多少”。 于是 S = lower.S + lower.T · qcell · fraction，而代码用 mix(lower.rgb, upper.rgb, fraction) 等价地插值前缀——因为 upper.S = lower.S + lower.T·q·(1−step_T)/σ，线性插值这两个端点正好等于局部段。

距离必须重新算：f 用的是 dsurface = |world − camera|，两个边界则用 deptha/cosθ 换算成径向距离，并且都要被可选的 start 裁剪。 用切片的对数比例当 f 会得到系统性偏差——这正是 CPU 回归 test_partial_cell_matches_actual_path_not_log_slice_fraction 守住的东西。

τ 很小时 1−step_T → 0，比值退化；代码在 τ < 0.001 时直接用 f，与一阶展开一致。

6.3 近灯/局部雾的边界纠偏

常系数重建仍有一个盲点：格子不知道雾是从格子内部的哪里开始的。 如果一块高密度局部雾只覆盖格子的后半段，而表面在格子前半段，整格平均会把后面的雾“泄漏”到表面前面。 灯核贴着一团雾时，这会表现为灯周围多出一圈不属于它的蓝雾。

默认开启的“近灯表面精细积分”只在同时满足以下条件时介入：存在局部雾、存在启用的点光、 片元到灯中心的距离在 max(1, R) 的 1–2 倍之间（权重 1−smoothstep(1,4,d²/R²)）， 且末格与局部雾的扩展包围球相交。 它保留 Froxel 前缀，只对最后一格用 2 段 × 4 次基础采样重新积分到表面，并按 局部雾的盒/椭球边界、灯的有限核心、全局 start 切段；接近末格末端时再平滑回缓存值，避免跨格跳变。

成本计入统计面板的 scene+UI；仍是数值积分，不解决全场景的 XY 走样，也不支持无限薄的雾层。 可以关掉做同视角 A/B。

6.5 显示：线性 HDR 只在这之后才被压扁

密度、源项、积分全程保留线性高动态范围，没有在中途截到 1。片元最后统一做：

display.glsl
Lexp = max(L, 0) · 2EV
Y = 0.2126 R + 0.7152 G + 0.0722 B  ;  C' = Lexp / (1 + Y)  （亮度 Reinhard）
超出色域时朝中性轴压缩，再 clamp 到 [0,1]，最后 sRGB 编码

自发光（灯核、火把焰、灯笼玻璃）另走一个显示算子。若直接算 map((R+E)·T + S)，E 是几千倍 HDR 峰值时，T 再小也会饱和成白点，“透过率衰减”在屏幕上根本看不出来。 代码改成先压缩发光增量，再乘 T：

display_emissive_surface
base = m(R·T + S)
glow = m(R + E) − m(R)  （m 为带曝光的线性显示映射）
display = clamp(base + T · glow, 0, 1)

纯灯核 R=0，普通材质的 emission 也走同一算子。无雾时 T=1，结果仍是原来的 m(R+E)；浓雾时发光增量按 T 淡出，而不是靠 HDR 饱和维持白点。 这是有意的显示取舍，不改变照明强度 I/R，也不改变体积积分出的 S/T。 它不是物理 HDR 合成，也不等价于 bloom；当前管线是 SDR sRGB 输出，不是 PQ/HLG。

07局部雾与控制点叠加介质

全局雾是“整片空气”，局部雾是可摆放在场景里的另一团介质：盒形或椭球形， 可以有边缘淡出、3D 密度纹理，或者由若干控制点程序化生成。它不是透明几何，不写深度、不投几何阴影， 只在注入/积分时增加消光与散射。

7.1 一个 ECS 实体

Transform  +  FogVolume  [+ FogDensityTexture]  [+ FogControlField]

Transform.scale 是完整尺寸/直径，不是半径；局部坐标范围是 [−0.5, 0.5]³。判断一个世界点是否在雾体内： 

local = world_to_local * p;
q     = abs(local) * 2.0;                    // 映射到 [0,1]
r     = shape == box ? max(q.x, max(q.y, q.z)) : length(q);
if (r >= 1) return 0;
fade  = 1 - smoothstep(1 - edge_fade, 1, r);
σ     = density * fade * modulation;

盒形用切比雪夫范数 max|q|，椭球用欧氏范数 |q|；两者在边界都是 1。 edge_fade 是相对半径的过渡宽度，smoothstep 让边缘没有硬壳。 外面还有一层包围球提前退出：|p − center| > bounds.w 时直接返回 0， 避免对每个雾体都做完整变换。

7.2 密度来源：均匀 / 3D 纹理 / 控制点

来源调制方式备注
均匀modulation = 1只有形状和边缘淡出
3D 纹理mix(1, tex, strength)R8 raw 或 builtin:cloud；最多 4 种，32³ 重采样，支持 tiling/offset/repeat
控制点场点核求和 → 1−exp(−Σ) → 梯度噪声启用时覆盖纹理来源；最多 32 点

纹理不是直接乘到全局雾上，而是作为这个雾体内部的密度调制。多个雾体的消光相加：

fog_medium
σt,total = σglobal + Σi σi
σs,total(RGB) = σglobal·Cglobal·albedo + Σi σi·Ci·albedoi

相加而不是平均，所以两团雾重叠的地方更浓、颜色也按各自的散射系数叠加；不会出现“后一个雾体把前一个的颜色覆盖掉”。 所有雾体共用全局的 HG g，没有逐体积相函数，也没有 RGB 吸收（消光仍是标量）。

7.3 控制点：用几个球核“捏”出云

每个控制点有局部 [0,1]³ 位置、半径、密度、柔和度。GPU 先生成 64³ 的密度网格，再在采样时三线性查询：

control_density.comp
d(p) = Σi ρi · [ 1 − smoothstep(1 − softi, 1, |p − ci|/ri) ]
d ← 1 − exp(−d)  （平滑有界并集，重叠变浓但不会无限叠加）
d ← d · mix(1, smoothstep(0.2, 0.8, noise), noise_strength)

噪声是 1–5 层梯度噪声，每层频率翻倍、振幅减半；超过网格 Nyquist 的 octave 会被 1 − smoothstep(16, 32, frequency) 衰减掉，避免把走样烘进缓存。 64³ 的网格每槽 1 MiB，预留 16 槽共 16 MiB，按交换链图像独立；静态场生成一次后复用， 动画只重生成发生变化的槽位。

点的动画用每场独立的归一化周期，只由世界 tick 推进：频率取 1–8 的整数，轨道幅度按初始位置到边界的余量收紧， 噪声位移也沿闭合轨道。所以一个周期后密度场回到原始相位——这是程序化循环， 不是流体或湍流输运。暂停/单步沿用全局动画控制。

7.4 和全局雾的交互

  • 局部雾的近端不受全局 start 裁剪；start 只门控全局介质的注入，避免在相机附近挖出一个只属于全局雾的空洞。
  • 太阳/点光阴影同样影响局部雾里的散射；灯核附近还会触发 6.3 的末格精细积分。
  • 雾体不进入实例绘制、不投几何阴影、不写深度；水面也不进入 shadow pass，所以透明物体不会在雾里切出阴影。
  • 最多 16 个活动雾体和 4 种纹理；超过上限会明确报错，不静默截断。小于体元的薄雾仍可能欠采样。
  • 变换动画每帧改矩阵时没有运动矢量补偿，快速移动的雾团可能有时域拖影；优先正确性。
为什么灯靠近雾团时是“蓝晕”而不是白球：先看调试视图 2（散射）确认介质贡献；再看 1（透过率）。 可能是旧 start 挖掉了近场、真实可见光程变短、或者灯核在显示阶段趋白。三者不是同一个 bug， 不能只凭一张截图归因。

08旧解析模型对照历史归档

在换成 Froxel 之前，这个示例用世界坐标的解析密度 + 闭式高度积分做雾。它已经不再参与渲染， 但推导很干净，而且解释了“为什么天空和地面在水平线处能无缝接上”。理解它也有助于看清当前实现多付了什么成本、换来了什么。

8.1 密度与闭式积分

旧模型的密度
σ(p) = anim(p, φ) · [ σbase + σmist · e−k·max(py−ground, 0) · N(pxz) ]

基础项是常数，沿射线直接是 σbase · span。高度项要算 ∫ e−k(y(s)−ground) ds。令 y(s) = y0 + dys， 当整段都在参考面以上时：

高度项闭式
∫ab e−k(y0+dys) ds = e−k y0 · (1 − e−k dy(b−a)) / (k dy)
dy → 0 时退化为 e−k y0 · (b−a)； y(s)=ground 处切成两段（下段密度取满）。

交点是 tcross = −(oy − ground)/dy：落在区间内就切段， 否则整段同侧。噪声没有闭式，旧实现取射线中点采样，再按 w = 1/(1 + span·noise_scale) 向均值 1 收敛——长射线趋于噪声平均， 远处不会出现格子斑块。这是近似，不是精确积分。

合成
T = e−τ  ;  C = background · T + atmosphere(dir) · (1 − T)

8.2 地平线为什么没有接缝

关键在于：天空 pass 直接输出 atmosphere(dir)，而地面几何的 in-scatter 用的是 同一个函数、同一个方向。于是远处的几何被雾完全遮住时，极限颜色正好等于该方向的背景色， 在构造上连续。而 atmosphere 的两个分支在地平线处取值相同：

  • dir.y > 0：天空渐变，从地平线色到天顶深蓝；
  • dir.y < 0：雾海渐变，从同一个地平线色出发，向下收敛到 fog_color；
  • 两者在 dir.y = 0 都等于 horizon 色，所以没有硬边。

旧 README 特别强调过：天空不能再被本地高度雾洗一遍，否则天空浓淡会随相机高度变化， 而且和地面雾的极限色对不上，水平线必然出现一条硬边。这是“背景色与散射色必须是同一函数”的经典约束。

09边界、参数与代码地图收尾

9.1 已知限制（不要误读为 bug）

物理近似

  • 只有单次散射：厚雾里缺少多次散射的“补光”，可能偏暗、偏平。
  • 没有 CSM；太阳阴影覆盖 48 单位，区域外按可见处理。
  • 水面与自发光体不投阴影；薄小遮挡可能闪烁或漏光。
  • 相函数全局共享一个 g，不支持逐体积；消光是标量，没有 RGB 吸收。
  • 点光阴影最多 5 盏，UBO 最多 8 盏。

离散化近似

  • XY 一格 8×8 像素（或被 192×128 上限放大），细光束/薄边缘会被抹宽。
  • 薄雾层、高频 3D 纹理可能欠采样，需要加切片或缩小像素步长。
  • 时域没有运动矢量与深度历史；快速转头会降低历史权重，薄遮挡可能拖影。
  • 近灯边界用末格精细积分缓解，但不是精确面积光软阴影。
  • 自发光显示算子是艺术取舍，不是物理 HDR 合成。
